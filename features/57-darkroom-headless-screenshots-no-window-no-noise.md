# 57. Darkroom — Headless Capture: Real Screenshots, No Window, No Noise

> The dev screenshot modes already render the truth. Just stop shoving a window in the human's face and blasting the ambient drone while they're working.

**The idea** — A headless capture mode for the existing `QC_*` screenshot tools (`QC_GALLERY`, `QC_LEVELSHOT`, `QC_ITEMSHOT`, `QC_WEAPONSHOT`, `QC_SHOT`). Today every one of them spins up a *visible* 1280×720 window that pops over whatever the human is doing and plays the full sound set (ambient loop + every SFX the run triggers) while it works. Darkroom keeps the rendering exactly as-is — real GPU, real swapchain, pixel-identical PNGs — but creates the window **unmapped** (`visible: false`) so nothing ever appears on screen, and **mutes audio** for the duration. Same screenshots, zero interruption.

**Why it's worth it** — The agent/dev loop leans on these shots to eyeball rigs, levels, pickups and view-models after a change (see the memory note: *this box has a GPU+display, so run/screenshot the game to verify visual changes*). But every verification pass hijacks the desktop and the speakers. The fix is nearly free precisely *because* the capture path already reads from the window's render target, not the composited screen — `Screenshot::primary_window()` grabs the rendered texture regardless of whether the window is mapped, so an invisible window screenshots fine. We keep the real GPU (no software-rendering fallback, no xvfb, no new deps) and just hide the surface.

**How the dev uses it** — Identical commands, one extra flag (or auto-on whenever a screenshot mode is active): `QC_HEADLESS=1 QC_LEVELSHOT=1 cargo run` builds every level and drops `levelshot_<n>_<slug>.png` without a window ever flashing and without a sound. The PNGs are byte-for-byte what the visible mode would have produced. Leave the flag off and the modes behave exactly as today (handy when you *do* want to watch it run).

**How it fits QUAKECLONE** — The hooks already exist. `main.rs:65` computes a `preview` flag for the four shot modes and uses it at `main.rs:79`/`:84` to force a small windowed mode; Darkroom adds `visible: false` to that same `Window` (gated on the new env flag, defaulting on for `preview` + `QC_SHOT`). Audio is Bevy's stock `AudioPlugin` in `DefaultPlugins` (`main.rs:74`) with the project's `audio::AudioPlugin` (`main.rs:157`) layering `AudioPlayer`s on top — muting is either `.disable::<bevy::audio::AudioPlugin>()` on `DefaultPlugins` (cleanest: `AudioPlayer`s go inert, zero overhead) or a `GlobalVolume` of 0. The capture call (`levelshot.rs:84`, `main.rs:252`, and the sibling shot modules) is **untouched**. One caveat to handle: `QC_SHOT` runs the live game path, which calls `player::grab_cursor` (`main.rs:193`) — on an invisible window that should be skipped in headless mode so it can't grab the human's real pointer (the gallery/levelshot/itemshot/weaponshot modes never grab the cursor, so they're clean).

**Build sketch** — (1) Add `headless` from a `QC_HEADLESS` env var near `main.rs:65`, default-true when `preview || QC_SHOT`. (2) Set `visible: !headless` on the primary `Window`. (3) When headless, `.disable::<bevy::audio::AudioPlugin>()` (or insert `GlobalVolume(0)`). (4) Skip `grab_cursor` when headless. (5) Verify on this X11/GPU box that an unmapped surface yields a valid PNG and doesn't flash — winit's `visible:false` is unmapped-from-creation, so it should be silent. Fallback if a compositor refuses to present an unmapped surface: render each shot camera to an `Image` render target + readback with `primary_window: None` and a `ScheduleRunnerPlugin` driver (true windowless, more code), or run under `xvfb-run` (zero code, but needs the package installed and likely drops to lavapipe software rendering — slower, slightly different output).

**Effort** — **S.** Mostly a few lines at the plugin/window setup in `main.rs`. The only real risk is the X11 unmapped-surface-screenshot check; the render-to-image and xvfb fallbacks de-risk it if needed.
